# ДЗ №5. Оптимизация spark: cache и партиции

## 1. Задача

Подсчёт запросов по хостам из ДЗ №4. Лог `NASA_access_log_Jul95`: 205 МБ, 1 891 715 строк. После фильтрации: 1 891 700 запросов, 81 982 хоста, 15 строк отброшено.

```python
LOG_RE = r'^\S+ \S+ \S+ \[[^\]]+\] "[^"]*" \d{3} \S+$'

df = (spark.read.text(LOG)
      .filter(F.col("value").rlike(LOG_RE))
      .select(F.substring_index("value", " ", 1).alias("host")))

df.groupBy("host").count().collect()
```

## 2. Методика

Spark 4.0.1, `local[*]`, 8 ядер. После прогрева выполнено 5 раундов по 3 обращения к каждому варианту. Каждый раз заново выполняется `groupBy().count().collect()` над промежуточным `df`.

Время измеряется через `time.perf_counter()`. Первое обращение с `cache()` включает заполнение кеша, два следующих используют его. Между раундами кеш освобождается через `unpersist(blocking=True)`.

В таблице приведены медианы. В столбце «Всего» указана медиана суммы трёх обращений. Она может отличаться от суммы медиан отдельных обращений.

## 3. cache к промежуточным данным

```python
df = hosts().cache()
for _ in range(3):
    rows = df.groupBy("host").count().collect()
df.unpersist(blocking=True)
```

Кешируется колонка `host` после фильтрации, до агрегации. Повторные обращения пропускают чтение текста, фильтрацию и извлечение хоста. Агрегация и её shuffle выполняются заново. Использование кеша подтверждено узлом `InMemoryTableScan` в плане.

## 4. Изменение числа партиций

```python
df = hosts()
df = hosts().coalesce(2)
df = hosts().repartition(16)
```

Число партиций промежуточного `df` до агрегации: 8, 2 и 16 соответственно. Проверено через `df.rdd.getNumPartitions()`. В этих вариантах кеш не используется.

## 5. Результаты

Время в секундах, медиана 5 раундов.

| Вариант | Партиций df | Первое | Второе | Третье | Всего |
|---|---|---|---|---|---|
| Без изменений | 8 | 2,427 | 1,967 | 1,633 | 5,790 |
| `cache()` | 8 | 3,054 | 1,086 | 1,225 | 5,763 |
| `coalesce(2)` | 2 | 4,596 | 3,203 | 2,961 | 10,759 |
| `repartition(16)` | 16 | 3,039 | 2,887 | 4,345 | 10,502 |

С `cache()` второе обращение быстрее в 1,81 раза, третье в 1,33 раза. Первое медленнее на 26 % из-за заполнения кеша. Общее время составило 5,763 с вместо 5,790 с, разница 0,5 %. При разбросе исходного варианта от 3,938 до 9,234 с устойчивое ускорение всей серии не подтверждено.

С `coalesce(2)` общее время выросло с 5,790 до 10,759 с, выполнение замедлилось в 1,86 раза. Объединение партиций не добавляет shuffle, но сокращение параллелизма с 8 до 2 задач замедлило обработку.

С `repartition(16)` общее время выросло с 5,790 до 10,502 с, выполнение замедлилось в 1,81 раза. Дополнительный shuffle и увеличение количества задач на этом объёме не окупились.

Для этой задачи оставлены исходные 8 партиций. Кеш ускорил повторные обращения, но с учётом заполнения заметного выигрыша по общему времени не получено.
